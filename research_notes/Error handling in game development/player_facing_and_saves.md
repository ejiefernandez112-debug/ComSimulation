# Player-facing failure handling and save-data protection in shipped games

Research date: 2026-10-03. Scope: what players see when something breaks, how games recover, and how they protect, version and migrate saves (incl. clock tampering in offline-progress games). Godot APIs and crash-reporting SaaS are deliberately out of scope (other researchers). Dates are given where a case study is old. Source quality is flagged where it is weak: "vendor blog" = Bugnet, a bug-tracking company whose blog reads as generic advice; "secondary" = news/guide sites; "community" = forums/wikis.

Project context used for the "missing" analysis: I read `scripts/autoload/economy.gd` and `scripts/sim/save_format.gd` in this repo (save to `user://save.json` via temp file + rename, one rotating `save.backup.json`, unreadable files renamed `save.unreadable-<time>.json`, newer `save_version` refused, step-by-step `_migrate()`, `_check_shape()` structural check, `_drop_unknown()` removes buildings/goods missing from data and tells the player). `data/game_config.json` sets `autosave_seconds: 30`; the game also saves after player actions (max once per second) and on close/pause/focus-out.

## 1. Graceful degradation and recovery: keep running vs. stop, safe modes, error codes, crash prompts

### Takeaway
Shipped games rarely stop on a non-fatal error. More often they switch off the risky part (mods, custom content, graphics settings), fall back to defaults, and give the player one short name or code they can quote to support. Prompts like "the game crashed last time" help, but they annoy people if they appear too often. X-Plane moved its prompt behind a held key for exactly that reason.

### Cited Findings
- **Destiny (Bungie) error codes**: each code is a single English word (animal, fruit or musical instrument, e.g. WEASEL, MARIONBERRY, BANJO) instead of digits. That makes codes easy to remember and to say to support, and the more often players mention a code online, the faster Bungie can locate the problem. — [PCGamesN](https://www.pcgamesn.com/destiny-2/error-codes); [GameRevolution](https://www.gamerevolution.com/?p=611399). Kotaku ranked the names (2018-04-20) without quoting Bungie on why. — [Kotaku](https://kotaku.com/destiny-error-code-names-ranked-1822201081)
- **Factorio, broken mod at startup**: instead of crashing to the desktop, the game shows a "Disable all mods / Restart / Exit" dialog, so the player can recover from inside the game without editing hidden config files. — [Factorio forums thread "Mod Errors leave the game broken"](https://forums.factorio.com/viewtopic.php?p=267919)
- **The Sims 4 turns mods off after patches** (since Dec 2015): after every medium or large update the game disables custom content and script mods, and a pop-up says so at the next launch. The player re-enables them under Options › Other › "Enable Custom Content and Mods", then restarts. EA's reason is that it can't be sure an unscreened mod still works after an update. EA advises loading a save with mods off first, exiting without saving, and checking with mod authors before turning mods back on. — [EA Help: Mods and The Sims 4 game updates](https://help.ea.com/en-us/help/the-sims/the-sims-4/mods-and-the-sims-4-game-updates); [SimsCommunity (2015-11-19)](https://simscommunity.info/2015/11/19/the-sims-4-automatic-disabling-of-mods-and-cc-when-updating-coming-in-december/)
- **X-Plane "safe mode"** (Laminar Research blog, 2015-08-21): when X-Plane detected that its last run crashed, it offered on the next start to reset rendering settings, because an over-ambitious setting could lock users out. From 10.40 beta 10 this became available "if and only if you start the sim with the shift key held down", since the automatic prompt annoyed users with multi-machine setups. — [X-Plane Developer blog](https://developer.x-plane.com/2015/08/a-slightly-better-safe-mode/)
- **Out of the Park Baseball, "crashed on startup flag"**: if the game had trouble starting, it tells the player so and automatically resets window size, full-screen preference and skin to defaults. Support then escalates one change at a time (render-mode command-line flags, driver reset, reinstall). — [OOTP Developments wiki](https://wiki.ootpdevelopments.com/index.php?oldid=2357)
- **Metro 2033** asks "previous launch unsuccessful, would you like to start the game in safe mode". F1 2021 has a `-safemode` launch flag that boots at the lowest resolution and graphics settings. — [Steam discussion (Metro 2033)](https://steamcommunity.com/app/43110/discussions/0/864948299980575828); [EA Answers HQ PC troubleshooting](https://answers.ea.com/t5/Technical-Issues/PC-Troubleshooting-Information/td-p/11213041) (snippet-level; F1 detail not verified on the page)
- **Cities: Skylines II error pop-up**: shows the exception with "Continue" and "Quit game", plus a "Copy" button that puts the error text on the clipboard. Players report a failure mode: a broken mod raises the pop-up over and over, so "Continue" never reaches the menu where the mod could be switched off. — [Steam discussion](https://steamcommunity.com/app/949230/discussions/0/4361249459071461316); [Steam discussion](https://steamcommunity.com/app/949230/discussions/0/634542138933121782)
- **Paradox Crash Reporter**: appears when a Paradox game (EU4, HOI4, …) quits unexpectedly and offers to send the crash. Crash folders are written to `Documents\Paradox Interactive\<Game>\Crashes\<game>_<date-time>\` (with `logs\error.log` and `exception.txt`). Players report the reporter sometimes fails to connect. — [Paradox forum](https://admin-forum.paradoxplaza.com/forum/threads/constant-crashes-on-the-desktop-also-wont-let-me-send-the-crash-report.1733922); [Steam discussion (HOI4)](https://steamcommunity.com/app/394360/discussions/2/595140603083229058)
- **Factorio automatic crash-log upload** (FFF #231, 2018-02-23, v0.16.24): see §2. It is opt-out, and within two days it found crashes nobody had reported. — [Factorio FFF #231](https://factorio.com/blog/post/fff-231)
- **Minecraft** has a deliberate "safest possible crash" debug key (hold F3+C) for testing the crash path. — [Minecraft Wiki: Crash](https://minecraft.wiki/w/Crash)

### Inferences
- Common pattern: (1) isolate the part most likely to be at fault (mods, CC, graphics settings, a single broken object), (2) disable or reset it automatically, (3) tell the player in one plain sentence what was switched off and how to switch it back. The project already does a version of this for unknown buildings and goods (`_drop_unknown()` plus a player note), much like SMAPI (§6).
- The Cities: Skylines II loop shows that an error dialog must not be able to block the way out. Repeated errors should be grouped or suppressed after the first, and the player must still reach "Quit" or "Disable".
- A "last session ended unexpectedly" flag (marker written at start, cleared on clean exit) is cheap, but X-Plane's experience says to offer it quietly or rarely rather than as a nag. On Android, the OS often kills backgrounded apps without a clean exit, so a naive marker would fire falsely all the time (my inference, not sourced). It should only count crashes while the game was in the foreground.
- **Missing in this project**: no short, quotable failure codes. Current player messages are good plain English ("The save file is damaged.", "The save was made by a newer version of the game.") but carry no stable identifier such as `SAVE-DAMAGED` or `SAVE-NEWER` that a player could paste into an email. There is also no "last run crashed" detection and no safe-start option.

### Gaps
- Bungie's own help article on error codes returned HTTP 403, so the "why animals" explanation comes from secondary sites only.
- I found no primary source for automatic restart after a crash in mobile sim games. On Android the OS handles relaunch, and I did not find game-specific write-ups.

## 2. Error UX case studies in sim/management games, and what makes them useful

### Takeaway
The systems players tolerate and developers value share four traits. They write a plain-text log automatically, with version, OS, hardware and mod list. They keep the previous session's log. They give a one-click way to turn that log into a shareable link or file, not a screenshot. And they point at the likely culprit by name (the first error, the first mod in the stack trace). Automatic upload catches far more crashes than forum reports, but it can't replace a human description and a save file.

### Cited Findings
- **Factorio logs**: each session writes `factorio-current.log` and keeps `factorio-previous.log` in the user-data folder next to saves and mods. The log records build and version, OS, launch arguments, hardware, graphics, mod load order, map loading and system date/time, and it is "required in any official bug report". — [Factorio Wiki: Log file](https://wiki.factorio.com/Log_file)
- **Factorio desync reports** (FFF #188, 2017-04-28, v0.15): on a multiplayer desync the game writes `%AppData%/Factorio/archive/desync-report-<date>_<time>.zip`, containing both the server's and the client's game state, which developers compare to find the divergence. The player is re-synced by re-downloading the map. Developers ask for reports on the official bug forum with reproduction steps ("load this save, wait for friend to connect, rotate this inserter…"); reports posted on Steam, by PM or by email risk being missed. — [Factorio FFF #188](https://factorio.com/blog/post/fff-188); [Factorio Wiki: Desynchronization](https://wiki.factorio.com/Desynchronization)
- **Factorio crash-log upload** (FFF #231, 2018-02-23, v0.16.24): "in its dying moments" the crashing game starts a separate process that uploads `factorio-current.log` (rarely a minidump) over HTTPS. The upload holds basic system info (CPU, GPU, free memory), display settings, the operation log and the main-thread stack trace. The server groups identical stack traces so developers can rank crashes by frequency. Uploading is **opt-out** in Options, because developers expected opt-in to get almost no participation. Logs were later sanitised (e.g. IP addresses removed) and the EULA updated. Results: hundreds of logs in two days, and developer Rseding fixed 12 crashes that had never been reported on the forum. The top crash (61 instances, `EntityRenderer::prepareRow`) happened only on AMD Ryzen CPUs. Developers still asked for forum reports, because automatic logs have no reproduction steps or saves. — [Factorio FFF #231](https://factorio.com/blog/post/fff-231)
- **RimWorld (modded)**: the community standard is HugsLib's Log Publisher. The player presses Ctrl+F12 in game, clicks Upload, then Copy, and gets a gist.github.com link with the full log *and* mod list. Many mod authors require that link in bug reports. Raw logs otherwise sit in the game's data folder (older builds: `RimWorldWin64_Data\output_log.txt`). — [Steam Workshop bug-report rules](https://steamcommunity.com/workshop/filedetails/discussion/1541721856/1735468061769788888/?ctp=9); [Steam Workshop discussion](https://steamcommunity.com/workshop/filedetails/discussion/761421485/600788331688728951)
- **RimWorld error style**: per the modding wiki, RimWorld "will not warn you: at best it will overload you with errors, at worst it will refuse to start". Errors cascade, so the first one is usually the real cause (e.g. "Could not resolve cross-reference: No SoundDef named Slurp found to give to ThingDef SomeName"), and NullReferenceException is the most common type. — [RimWorld Wiki: Modding troubleshooting](https://rimworldwiki.com/wiki/Modding_Tutorials/Troubleshooting)
- **RimWorld mod-mismatch dialog**: loading a save after adding or removing mods shows a "your mods look different" warning with a "load anyway" choice. Players report it is usually harmless. — [Steam discussion](https://steamcommunity.com/app/294100/discussions/0/144512526681622415); [Steam discussion](https://steamcommunity.com/app/294100/discussions/0/3944650462449908329)
- **Stardew Valley + SMAPI**: players upload their SMAPI log to the web parser at smapi.io/log and share the resulting link. The parsed page lists, at the very top, every installed mod that needs an update. For oversized logs, players paste from the top through the first couple of errors. — [Stardew Valley Wiki: Modding troubleshooting](https://stardewvalleywiki.com/Modding:Player_Guide/Troubleshooting)
- **Minecraft Java**: on most crashes the window closes and the launcher shows a crash screen. A timestamped plain-text report is written to `.minecraft/crash-reports/`. It opens with a random joke line ("Who set us up the TNT?"), then the description and stack trace, "A detailed walkthrough of the error", and System Details (OS, Java, mods). JVM-level crashes write `hs_err_pid<PID>.log` instead. A server-side crash shows a "Saving [world]" screen before the window closes. — [Minecraft Wiki: Crash](https://minecraft.wiki/w/Crash)
- **Fabric (Minecraft mod loader) player docs**: share crash reports as a link via a paste site (GitHub Gist, mclo.gs, Pastebin), "not screenshots". Read the main summary, then the System Details mod list. The first mod named in the stack trace is usually responsible. — [Fabric docs: Crash reports](https://docs.fabricmc.net/26.1.2/players/troubleshooting/crash-reports)
- **Oxygen Not Included (Klei)**: support asks players to send `Player.log` (`%appdata%\..\locallow\klei\Oxygen Not Included`) *before relaunching*, so the next session doesn't overwrite the error. Crash dumps go to `%APPDATA%\..\Local\Temp\Klei\Oxygen Not Included\Crashes`. Klei may also ask for the save, which sits in the `auto_save` folder unless the player saved manually. Local and cloud saves are separate folders (`...\save_files` and `...\cloud_save_files`). Players report the in-game crash reporter failing, e.g. with saves over about 12 MB. — [Klei support](https://support.klei.com/hc/en-us/articles/360029555392); [Klei bug tracker](https://forums.kleientertainment.com/klei-bug-tracker/oni/crash-reporting-still-broken-r21712/)
- **Cities: Skylines II**: its error pop-up has a "Copy" button. Players paste the text into Notepad to find the failing mod. NullReferenceExceptions typically come from mods referencing assets that no longer exist after an update. — [Steam discussion](https://steamcommunity.com/app/949230/discussions/0/4361249459071461316); [Paradox forum](https://admin-forum.paradoxplaza.com/forum/threads/nullreferenceexception-object-reference-not-set-to-an-instance-of-an-object.1667427)

### Inferences
- What helps developers: the version, OS, hardware and content list are captured automatically; a stack trace is grouped by signature; the previous session's log is kept; and crashes are uploaded or easy to share. What helps players: one action produces a link or file to share; the message names the culprit ("Did you remove a custom NPC mod?"); and a known place to look exists. Klei's "send the log before relaunching" shows the cost of keeping only one log. Factorio keeps `-previous.log` to avoid that.
- For a solo developer, Factorio's numbers (12 unreported crashes fixed in two days) are the strongest argument for some automatic crash signal eventually. The specific tooling belongs to the other research tracks.
- **Missing in this project**: no player-visible log file convention, no "previous log" kept for support, and no one-tap way for a player to hand over diagnostics. These are Godot-specific details for other researchers.

### Gaps
- I could not open Klei's crash-report bug pages (HTTP 403), so I can't confirm the exact layout of ONI's in-game crash screen (e.g. whether it has an "upload save" checkbox).
- I did not find primary docs for Kerbal Space Program's crash UX or for Cities: Skylines 1's built-in error handling.
- I did not review Paradox dev diaries on crash reporting.

## 3. Save-integrity techniques, platform backup/cloud, and real corruption incidents

### Takeaway
Shipped games stack several defences: atomic replace (write a temp file, then rename), several *time-spaced* backups (Sims 4 keeps 5, KSP 5, SMAPI 10 daily, Antimatter Dimensions 8 interval slots), checksums with an alternate slot (Pokémon), and keeping damaged files rather than overwriting them. The incidents show the gaps. A temp-file swap does not make the data durable unless it is flushed to disk first (the ext4 incident, 2009). Size limits can silently corrupt saves (Cyberpunk 2077, 2020). And writing too often has real costs (Windrose, 2026).

### Cited Findings
#### Write strategy
- **Factorio**: a developer (posila) explained that "the game doesn't overwrite saves, it renames the old one, saves new one and when that succeeds deletes the old one". In the same thread he said making 0.17 able to write 0.16-format saves "would take more than 144 hours", so there is no downgrade path. — [Factorio forums (2019, v0.17.23)](https://forums.factorio.com/viewtopic.php?p=419421)
- **The ext4 zero-length-file incident** (Linux, March 2009): apps that wrote a new file and renamed it over the old one *without* `fsync()` could end up with an empty file after a crash. ext4's delayed allocation could commit the rename before the data. KDE and GNOME config files were hit. Ted Ts'o's position: apps that need data on the media should call `fsync()`/`fdatasync()`, "that's exactly what those system calls are for". Kernel 2.6.30 added workarounds, including forced block allocation when a file is renamed over another. — [LWN: ext4 and data loss](https://lwn.net/Articles/322823/); [LKML patch "ext4: Automatically allocate delay allocated blocks on rename"](https://lkml.iu.edu/hypermail/linux/kernel/0906.1/01345.html)
- **Stardew Valley** writes saves under a temporary suffix (`_STARDEWVALLEYSAVETMP`) and keeps `_old` copies (`_SVBAK` on iOS). A known manual recovery is renaming leftover temp or `_old` files. The game saves only at the end of an in-game day. Each save folder needs both the main file and `SaveGameInfo`. SMAPI's bundled SaveBackup mod keeps up to 10 daily backups. — [Stardew Valley Wiki: Saves](https://stardewvalleywiki.com/Saves)

#### Multiple backups
- **The Sims 4** keeps up to six versions per slot: `Slot_XXXXXXXX.save` plus `.ver0` (newest backup) to `.ver4` (oldest). Restoring means renaming a `.verN` file to drop the suffix, losing "no more than a few Sim hours". — [SimsCommunity (2015-02-13)](https://simscommunity.info/2015/02/13/sims-4-tutorial-restore-previous-saved-game/); [EA Answers HQ: backing up saves](https://forums.ea.com/blog/the-sims-game-info-hub-en/backing-up-saves-in-the-sims-4---keep-your-sims-safe/12913482)
- **Kerbal Space Program**: each save folder has a `Backups` folder of rolling `persistent.sfs` copies. `settings.cfg` defaults are `SAVE_BACKUPS = 5`, `AUTOSAVE_INTERVAL = 300` (seconds) and `AUTOSAVE_SHORT_INTERVAL = 30`. Autosave only overwrites `persistent.sfs`, never named saves. — [Steam discussion (KSP)](https://steamcommunity.com/app/220200/discussions/0/1698294337791135092); [KSP forum](https://forum.kerbalspaceprogram.com/topic/188586-how-to-restore-persistent-file-after-power-interruption)
- **Antimatter Dimensions** (open-source idle game): 3 save slots plus 8 automatic backup slots. Four "online" slots refresh after 1 min, 5 min, 20 min and 1 h of play. Three "offline" slots are written *just before offline progress is applied*, picked by time away (10 min, 1 h, 5 h). One "reserve" slot is kept for emergencies. Backups can be exported and imported as a file. — [AD source: storage.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/storage.js)
- **Minecraft** keeps `level.dat_old` next to `level.dat` (the world's core settings file) as a one-step fallback, and its wiki still tells players to copy their saves folder regularly. — [Fabric/Minecraft troubleshooting](https://docs.fabricmc.net/1.21.4/players/troubleshooting/crash-reports); [Minecraft Wiki: Crash](https://minecraft.wiki/w/Crash)

#### Checksums and alternate slots
- **Pokémon (Gen III/IV handhelds)**: the game stores two full saves in alternating slots, each protected by checksums. On load it recomputes the checksums. If the newest slot fails and the older passes, it tells the player the save was corrupted and loads the previous one. — [PokéBase Q&A (community)](https://pokemondb.net/pokebase/396866/what-caused-this-save-file-been-corrupted-previous-save-loaded); [TASVideos forum](https://tasvideos.org/Forum/Topics/27300)
- Generic vendor-blog advice (lower quality): checksums catch what atomic writes can't, such as disk bit rot, serialisation bugs and external edits. Store a hash in a header or trailer, recompute it on load, and keep a `.bak` of the previous save made before the rename. — [Bugnet: prevent and recover from save corruption](https://bugnet.io/blog/how-to-prevent-and-recover-from-save-corruption); [Bugnet: debug save corruption](https://bugnet.io/blog/how-to-debug-game-save-corruption-bugs)

#### Incidents
- **Cyberpunk 2077** (Dec 2020): saves became corrupt once they passed 8 MB, which was easy to reach with heavy crafting and big inventories. Hotfix 1.06 removed the limit on PC but couldn't repair saves already damaged. — [TechSpot](https://www.techspot.com/news/88082-latest-cyberpunk-2077-patch-fixes-saved-game-corruption.html); [TheSixthAxis (2020-12-24)](https://www.thesixthaxis.com/2020/12/24/cyberpunk-2077-hotfix-1-06-removes-the-8mb-save-file-limit/)
- **Windrose** (early-access survival game, launched 2026-04-14): players measured about 15–30 MB/s of disk writes, up to about 108 GB per hour. Causes were a RocksDB save store with a 1 MB write-ahead-log budget plus an autosave that ran "roughly every game tick while moving" and produced dozens of backup files a minute. Patch 0.10.0.4 cut writes by 60–75% (below 1 MB/s idle). 0.10.0.5 replaced continuous backups with saves every 10 minutes of play and on exit. — [AllThings.How (secondary)](https://allthings.how/windrose-high-ssd-usage-explained-and-fixed-patch-0-10-0-4/)
- Forum and vendor guidance on autosave rate: save on meaningful state changes and batch them. One indie developer moved from per-second saves to every 60 s. Small files and flash wear-levelling make the wear risk smaller than people fear. — [itch.io thread](https://itch.io/post/8558484); [Bugnet (vendor blog)](https://bugnet.io/blog/how-to-fix-game-saving-progress-too-frequently)

#### Platform backup and cloud (Android first, then PC)
- **Android Auto Backup** (Android 6.0+, on unless `android:allowBackup="false"`): backs up shared prefs, `getFilesDir()`, `getDir()`, databases and `getExternalFilesDir()`. It excludes cache, code cache and `getNoBackupFilesDir()`. The quota is 25 MB per app; over quota, nothing is backed up. It runs at most once every 24 h, only when the device is idle, on Wi-Fi (unless the user allows mobile data) and with backup enabled; the docs warn some devices "may never back up". Only the latest backup is kept. Restore happens on (re)install, after the APK installs but before first launch. End-to-end encryption needs Android 9+ and a lock screen. Android 12+ uses `dataExtractionRules` with separate `<cloud-backup>` and `<device-transfer>` rules, and `allowBackup=false` may not block device-to-device transfer. Android 16 QPR2+ adds iOS transfer rules. The app is shut down during backup. Test with `adb shell bmgr backup|restore <pkg>`. — [Android Developers: Auto Backup](https://developer.android.com/identity/data/autobackup)
- **Android scoped storage (Android 11+)**: `Android/data/` is closed to other apps, including file managers. Stardew players report they can no longer back up or sync saves with tools like Syncthing, and they asked for a user-chosen save location (thread 2023-11-22, bumped 2024-03-25, no developer reply). — [Stardew Valley forums](https://forums.stardewvalley.net/threads/android-option-to-change-the-save-game-location.25172/latest); [Android Developers: Android 11 storage](https://developer.android.com/about/versions/11/privacy/storage)
- **Google Play Games Saved Games**: a snapshot is a binary blob (max 3 MB), a cover image (max 800 KB) and metadata (name, description, last-modified, played time). It must be enabled in Play Console, and the game must implement conflict resolution. Conflicts come from several devices, local-vs-cloud divergence, or a guest account with progress linking to an account that already has cloud data. Guidance: load the latest on start and resume, save at a reasonable rate, work offline and sync later, "never silently overwrite significant historical data", and warn before guest-linking replaces cloud progress. Guest progress is device-only. — [Android Developers: PGS Saved Games](https://developer.android.com/games/pgs/savedgames)
- **Steam Cloud**: Auto-Cloud needs no code and syncs configured paths at launch and exit. The ISteamRemoteStorage API needs code and lets the game choose what syncs. Valve advises splitting save data by how often it changes, keeping files small, using per-user paths and not syncing machine-specific settings. A single write can be at most 100 MB, and files over 256 MB sync slowly. — [Steamworks: Steam Cloud](https://partner.steamgames.com/doc/features/cloud)
- **Steam Cloud Sync Conflict dialog**: when local and cloud copies disagree, the client asks the player to keep the local files or download the cloud ones. Player guides stress that "local" and "cloud" are locations, not ages, and say to copy the save folder before choosing. — [Steam Community](https://steamcommunity.com/discussions/forum/1/4511002848512134204); [evetech guide (secondary)](https://evezone.evetech.co.za/daily-drop/steam-cloud-conflict-save-selection-guide)
- **Melvor Idle**: players report the cloud copy being treated as "latest" even when it is older than the local save, and complain that loading needs a connection plus several services. — [Steam discussion](https://steamcommunity.com/app/1267910/discussions/0/3040481812853593632/?l=italian); [itemlevel.net (secondary)](https://itemlevel.net/is-melvor-idle-online-only/)

### Inferences
- The project's current write path (temp file, rename, one backup, damaged file kept) matches Factorio and Stardew. Compared with good practice it still lacks four things:
  1. **Durability before the swap.** `economy.gd` stores the string, checks `get_error()` and closes, but never explicitly flushes or syncs to disk before renaming. The ext4 lesson says a rename can survive a power cut while the data doesn't. Android uses ext4/f2fs-style journaling filesystems (inference). Whether Godot's close or flush forces data to the storage device is a Godot question for the other researchers.
  2. **Verify after writing.** Nothing re-reads the temp file and parses it (running `from_text()`, i.e. the same shape check) before swapping it in. For a small JSON file this costs very little and catches truncation or serialiser bugs before they replace the good save.
  3. **Time-spaced backups.** The single `save.backup.json` is replaced on every save: every 30 s, after actions (max once a second), and on pause. So it is only seconds older than the main save. That protects against a torn write but **not** against a logic bug that writes bad-but-valid JSON (negative stock, a broken job). Within seconds both copies are bad. Shipped games keep copies spaced in time (Sims 4: 5 versions; KSP: 5; SMAPI: 10 daily; AD: 1 min/5 min/20 min/1 h plus pre-offline). A cheap equivalent: keep the last 2–3 saves plus "first save of this session", "first save of today", "just before offline catch-up" and "just before a migration".
  4. **"Start over" wipes the old game within about 30 s.** `start_new_game()` saves at once, which moves the old game into the backup slot. The next save (≤30 s later) deletes that backup, as the code comment admits. A dedicated, never-auto-deleted copy (like AD's reserve slot) would make "Start over" undoable.
- **Checksum: optional for this project.** JSON parsing plus `_check_shape()` already catches truncation and most damage. A hash mainly adds the ability to tell damage apart from hand-editing. For a single-player game a reasonable policy is "detect, note in the log, still load", not "reject". Pokémon's two slots with checksums is the classic pattern if stronger detection is ever wanted.
- **Android backup exposure.** If `user://` maps to the app's internal files directory (Godot detail to confirm), Auto Backup already covers it: at most once a day, latest copy only, 25 MB cap, restored only on reinstall or a new device. That is a useful safety net, not a backup system. Because `Android/data` is closed since Android 11, the player has no easy way to copy the save themselves. An in-game **Export/Import save** (share sheet or copy-to-clipboard text, as Antimatter Dimensions, Cookie Clicker and Melvor do with export strings) is the most practical player-side safety net.
- Unreadable files: each failed load creates `save.unreadable-<time>.json`. Nothing caps or reports how many pile up. Minor, but worth an occasional cleanup that keeps the newest few.
- For the later MMO/cloud phase: plan for Play Games' 3 MB snapshot cap and its conflict-resolution requirement. Show both candidates (played time, last-modified, cash) and never silently overwrite. The Melvor "older cloud wins" complaint is the failure mode to avoid.

### Gaps
- No authoritative numbers on flash wear from frequent small saves on phones. The project's ~3,000 small JSON writes a day is probably harmless, but I found no primary source quantifying it.
- No primary write-ups of save-corruption incidents in mobile farm/business games (Hay Day, Township, Idle Miner Tycoon). Those games are largely server-backed, which I could not verify from primary sources.
- Valve's own description of the Cloud Sync Conflict dialog wasn't found; only secondary descriptions.
- The claim that Factorio "does not validate the game state when it is saved, only when it is loaded" appeared only in a search snippet and could not be verified, so it is not used.

## 4. Save versioning and migration

### Takeaway
Long-lived games give every save a version number (one plain integer, not the display version). They upgrade old saves one step at a time through a chain of small, permanent functions. They fill missing fields from defaults. And they refuse or warn on saves from newer versions, because upgrades are one-way. Minecraft also offers a backup before upgrading. The project's design already matches this model. The main missing pieces are a pre-migration backup, a corpus of real old saves for testing, and better handling of saves from a newer version.

### Cited Findings
- **Minecraft data version**: every world stores an ever-increasing integer "data version", introduced in Java 1.9 (snapshot 15w32a, starting at 100), because display versions like "1.14" and "19w02a" can't be compared. Opening an *older* world prompts the player to back it up first. Opening a *newer* world warns that it may become corrupted. — [Minecraft Wiki: Data version](https://minecraft.wiki/w/Data_version)
- **Minecraft DataFixerUpper (DFU)** upgrades data one version at a time. Each chunk carries its own version and is upgraded when loaded, which is why worlds years old still open. Conversion is destructive and one-way, so older game versions can't read upgraded data. DFU is CPU- and memory-heavy at startup, and community mods such as LazyDFU exist just to defer it. — [GDLauncher docs](https://gdlauncher.com/docs/save-format-compatibility); [Madeline Miller blog](https://madelinemiller.dev/blog/minecraft-server-forceupgrade/); [ModpackIndex: LazyDFU](https://www.modpackindex.com/mod/21560/lazydfu)
- **Antimatter Dimensions** (idle game, 2016 to the Reality update 2021 to Steam 2022): `migrations.patches` is an object keyed by integer version (1…25+), and each patch mutates the save. Examples: `player.antimatter = new Decimal(player.money)` renames a field, and missing values get defaults (`?? Number.MAX_VALUE`). Patch 13, the Reality conversion, chains about 30 helpers (`normalizeTimespans`, `convertAutobuyerMode`, `fixChallengeIds`…). Load order: pre-Reality patches, then dev patches, then post-Reality patches, then a deep-merge with the default player object (fills any missing field), then the `SAVE_CONVERTED_FROM_PREVIOUS_VERSION` event fires. — [AD source: migrations.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/migrations.js); [AD source: storage.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/storage.js)
- **Factorio migrations** (mods and base game): `.json` migrations rename prototypes and `.lua` migrations edit loaded game state. Order is by mod, then by filename, and "all JSON migrations are applied before any Lua migrations". **Each save remembers which migrations it has applied**, so each runs exactly once per save. A rename keeps the entity's `unit_number` and stored references valid. A type change makes a new `unit_number` and breaks references. When a prototype is removed, references to it become invalid, and ghosts may be removed. — [Factorio Lua API: Migrations](https://lua-api.factorio.com/latest/auxiliary/migrations.html)
- **Factorio refuses newer saves** with an exact, explanatory message: "Map version 0.17.23-1 can't be loaded because it's higher than the game version (0.16.51-0)". A developer said writing older formats is impractical (">144 hours"). — [Factorio forums](https://forums.factorio.com/viewtopic.php?p=419421). The same error also shows up after crashes or game downgrades, and for very old saves players are told to load and re-save in an intermediate version. A claim that Factorio deliberately drops very old migrations "to clean code" appeared only in search snippets. — [Factorio forums](https://forums.factorio.com/viewtopic.php?p=576959)
- **The Sims 4 disables mods after each patch** (see §1). This is effectively version-gating third-party content rather than trying to migrate it. — [EA Help](https://help.ea.com/en-us/help/the-sims/the-sims-4/mods-and-the-sims-4-game-updates)

### Inferences
- The project's `_migrate()` (step chain `if version < 2 … < 5`, each step commented with the plan section) is the same shape as AD's patches and Minecraft's DFU. Its rule "add a step, never break old saves" is current practice. Three differences from the best examples:
  1. **No backup before migrating.** Minecraft asks the player. AD writes backup slots. The project's original file only survives until the second save after the upgrade, because the rotating backup is overwritten within seconds (§3). Keeping a permanent `save.v<old>.pre-migration.json` the first time an old save is upgraded costs nothing.
  2. **No migration test corpus.** CLAUDE.md says rule tests use their own test data. Good practice (inference, see Gaps) is to commit one real save from every `save_version` into `tests/fixtures/` and have the headless test load each through `from_text()`, checking it reaches the current version and passes the invariant checks (§6). Every save_version bump then adds a fixture.
  3. **Newer-version saves are handled like damaged ones.** From reading `economy.gd` `_load_game()`: when `from_text()` returns "The save was made by a newer version of the game.", the code renames the file to `save.unreadable-<time>.json`, tries the backup (usually also newer), and then **starts a new game** with a note. The file is kept, so nothing is lost. But the player effectively gets a fresh farm, and later saves pile on top of it. Factorio and Minecraft instead stop with a clear "update the game" message. This will matter more with Android Auto Backup restores, device transfers, sideloaded older builds and the future cloud sync. A dedicated path ("This save is from a newer version. Please update; your save hasn't been touched.") that does not start a new game or rename the file is safer.
- AD's final deep-merge with defaults is a cheap extra safety step: it adds any field a migration forgot. The project's `_check_shape()` rejects instead of filling. A mix (fill harmless optional fields with defaults, reject only when core data is missing) is more forgiving.

### Gaps
- I found no primary source (GDC talk, postmortem) describing studios testing migrations against a library of real player saves. The recommendation above is my inference from general practice, not a cited case.
- Stardew Valley's own version-to-version save migration code (e.g. 1.6's) and Paradox's save-compatibility policies were not researched.

## 5. Offline progress / idle games: clock changes, time zones, huge numbers, NaN, offline caps, anti-tamper

### Takeaway
Single-player idle games mostly *tolerate* clock cheating, or answer it with soft in-fiction consequences: Animal Crossing rots turnips, and Cookie Clicker slows the sugar lump. Few detect it hard, and hard enforcement shows up mainly where other players are affected (Egg, Inc. co-ops, reportedly). Offline gains are usually capped, by time (Melvor about 24 h) or by simulation limits (Antimatter Dimensions ticks, Clicker Heroes stopping when the idle run stalls). The good open-source example takes a backup *before* applying offline progress and validates numbers for NaN before saving.

### Cited Findings
- **Antimatter Dimensions**: stores `player.lastUpdate` and on load computes `Date.now() - player.lastUpdate`. Offline progress is a player option. The simulation floors ticks at 33 ms and caps them at 1,000,000. Players can "speed up" (halve the remaining ticks, less accurate) or "skip". It writes a backup slot *before* applying offline progress. — [AD source: storage.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/storage.js); [r/AntimatterDimensions: max offline ticks](https://red.127.pp.ua/r/AntimatterDimensions/comments/1kg34yc/max_offline_ticks)
- **Melvor Idle** caps offline progress at 24 hours (one source says 18 h, probably an older version). — [Steam discussion](https://steamcommunity.com/app/1267910/discussions/0/3823048293516778888); [Steam discussion](https://steamcommunity.com/app/1267910/discussions/0/591762563949134719)
- **Clicker Heroes**: offline progress simulates an "idle run" from the current build, so it naturally stops at the zone where idle damage can no longer kill enemies. Click skills and autoclickers don't count offline. The post also notes a crash or unexpected shutdown can stop offline earnings from being calculated. — [Clicker Heroes blog (2025-07-06; I'm not certain the blog is official)](https://blog.clickerheroes.com/?p=1902)
- **Animal Crossing (Nintendo)** treats clock changes ("time travel") as allowed but builds in *designed consequences* instead of blocking. In New Horizons any time travel rots stored turnips; going backwards resets Stalk Market prices and visitor schedules; future-dated newspaper articles are deleted; weeds may spawn; villagers need explicit permission to move out. New Leaf forced a falling stalk-market pattern after backward travel. Producer Hisashi Nogami: playing without time travel "would probably be the ideal way", yet the team chose systems over prevention. — [Nookipedia: Time travel](https://nookipedia.com/wiki/Time_travel)
- **Cookie Clicker**: setting the clock back makes the growing sugar lump "exposed to time travel shenanigans", so it takes an extremely long time to ripen. That is a soft penalty on the one timer worth exploiting. The July 2023 changelog lists "Better detection if offline production should be proceeded". The game also officially offers a "cheater" ascension name instead of punishing cheats. — [Steam discussion](https://steamcommunity.com/app/1454400/discussions/0/6821308966002606218); [Steam Workshop changelog](https://steamcommunity.com/sharedfiles/filedetails/changelog/3007363242?l=latam); [Cookie Clicker source mirror](https://gitea.suzanne.soy/suzanne.soy/Cookie-Clicker-Source-Code/src/branch/stable/README.md)
- **AdVenture Capitalist (Hyper Hippo)**: players have long used airplane mode plus moving the clock forward to farm offline money and skip unlock timers. A 2015 Steam thread shows no developer response and players believing "the devs didn't mind". One player notes **daylight-saving time changes alone caused timer glitches**. — [Steam discussion (Nov–Dec 2015)](https://steamcommunity.com/app/346900/discussions/0/492378806376401622)
- **Egg, Inc. (Auxbrain)**: v1.11 release notes reportedly let co-op members kick "time cheaters" (seen only in a search snippet; APKMirror returned 403). A low-quality site claims that opening the game with an earlier clock than last time pauses production for an hour (unverified). — [APKMirror: Egg, Inc. 1.11](https://apkmirror.com/apk/auxbrain-inc/egg-inc/egg-inc-1-11-release); [ExpertBeacon (unverified)](https://expertbeacon.com/can-you-get-banned-from-egg-inc/)
- **Indie anti-time-cheat advice** (engine forums): store the last-seen timestamp and flag it moving backwards beyond a tolerance (to allow for time zones). Show a neutral "please check your device clock" message. Penalties are possible, but the only robust fix is asking a server for the time. — [Unity Discussions](https://discussions.unity.com/t/simple-anti-time-cheating-on-android-ios/674418); [Solar2D forums](https://forums.solar2d.com/t/avoid-player-changing-time-to-cheat-in-game/343814); [Unity Discussions](https://discussions.unity.com/t/system-datetime-now-and-how-to-avoid-time-cheats/36906)
- **Vendor-blog advice** (lower quality): treat the device clock as untrusted. Clamp the offline window (e.g. 8 or 24 h) *before* multiplying by the production rate. Reset the anchor timestamp after granting, so time isn't counted twice. Detect "impossible" states instead of trying to stop every cheat: currency above what the elapsed time could produce, or negative values from overflow. — [Bugnet: offline earnings not capped](https://bugnet.io/blog/how-to-fix-offline-earnings-not-capped-granting-days-of-income); [Bugnet: idle offline progress wrong](https://bugnet.io/blog/how-to-fix-idle-game-offline-progress-wrong)
- **Huge numbers**: JavaScript doubles top out near 1.8e308, so idle games use big-number libraries. break_infinity.js (Patashu) replaces decimal.js for numbers up to about 1e9e15, favouring speed over accuracy, and is used by Antimatter Dimensions, where the 1.8e308 limit is literally the "Infinity" mechanic. Its sequel break_eternity.js reaches 10^^1e308. — [npm: break_infinity.js](https://npmjs.com/package/break_infinity.js); [jsDelivr: break_eternity.js](https://www.jsdelivr.com/package/npm/break_eternity.js)
- **NaN**: Antimatter Dimensions recursively scans the whole save for NaN, as a number or the string "NaN", and rejects such a save on import with "Could not load the save (format unrecognized or invalid)" (details in §6). — [AD source: storage.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/storage.js)

### Inferences
- **Clock policy for this project** (it uses unix-second timestamps through `TimeService.now()`, not countdowns):
  - *Time zones and DST*: unix seconds don't depend on the time zone, so moving across zones or a DST change can't change offline time, as long as no rule uses *local* calendar time. AdCap's DST glitch shows the risk if daily resets or "night" features are added later. Those should be defined in UTC or handle the jump explicitly.
  - *Clock moved backwards*: `economy.gd` already clamps offline time to ≥ 0 (`maxf(now - settled, 0.0)`), meeting the "never negative progress" rule. But jobs whose `started_at`/`finishes_at` are now in the "future" will **freeze until real time catches up**. That could be hours or months if the phone's clock had been wrong and was then auto-corrected. The debug-only `TimeService.warp` covers this for the developer, not players. Options: (a) accept the freeze as a natural cheat penalty (similar to Cookie Clicker's lump); (b) if the clock jumped back by more than a tolerance, shift every stored timestamp back by the jump (a single calculation) so the farm keeps running and the player keeps what they already got. Either way, record the event in the save notes and log.
  - *Clock moved forward*: tolerating it is the norm for single-player games (AdCap, Animal Crossing, Cookie Clicker). The project's natural caps (storage capacity, inputs, queue length) limit the gain like Clicker Heroes' "idle run stalls". Whether an explicit offline cap exists in `data/*.json` should be checked against plan.md. A cap belongs in data, not code, per the project's rules.
  - Keep a `max_seen_time` in the save so a "forward, collect, back, forward again" loop can't grant the same hours twice (inference from the vendor "reset the anchor" advice).
  - Before the MMO phase, decide whether competitive or shared features (trading, leaderboards) need server time. Egg, Inc.'s co-op kick shows enforcement becomes necessary exactly where cheating affects others.
- **Numbers**: money is already whole cents in a 64-bit int (save v4). `_whole_numbers()` only turns floats into ints below 9.0e15, which keeps precision safe. Overflow is unlikely for a farm-to-shop economy. NaN, INF and negatives are the realistic risks (e.g. a divide-by-zero in a price or wage formula). `_is_number()` in `save_format.gd` accepts any float, including NaN and INF, so these would pass the shape check (see §6).
- Offline catch-up is the riskiest single operation, because it applies a lot of change in one step. Antimatter Dimensions' "backup just before offline progress" is a direct, cheap pattern to copy.

### Gaps
- No primary sources found for clock handling in Hay Day, Township or Idle Miner Tycoon. They appear server-backed, which would make device clock changes irrelevant, but I could not confirm this from developer docs.
- Melvor Idle's official wiki page on offline progression returned HTTP 403. Its exact clock-backwards behaviour is unknown.
- Egg, Inc.'s time-cheat mechanics remain unverified.
- I found no r/incremental_games thread with developer statements on clock-cheat policy; only secondary summaries surfaced.

## 6. Invariants and self-checks at load/save time (repair and logging)

### Takeaway
The best examples check the save at load. They remove or default anything that refers to content that no longer exists, write one specific, plain-language line per repair ("Removed invalid villager X… Did you remove a custom NPC mod?"), and refuse to accept or write numerically broken state (NaN). The project already does the first half (structure check plus dropping unknown content with player notes). What's missing is a *value* check (NaN/INF/negatives, cross-references, timestamps) that also runs *before saving*.

### Cited Findings
- **SMAPI's bundled "Error Handler" mod (Stardew Valley)**: its SaveGame patch runs at load and finds content that no longer exists (custom buildings, villagers/NPCs, farm types from uninstalled mods, and null objects left by mods). It removes these or replaces them with defaults (an invalid farm type becomes the standard farm) and logs one line per repair, e.g. "Removed invalid building type '[type]' in [location] ([coords]) to avoid a crash when loading save '[folder]'. (Did you remove a custom building mod?)". — [SMAPI source: ErrorHandler/Patches/SaveGamePatcher.cs](https://git.nea.moe/github/SMAPI.git/tree/src/SMAPI.Mods.ErrorHandler/Patches/SaveGamePatcher.cs); [Stardew Valley forums](https://forums.stardewvalley.net/threads/i-deleted-a-npc-mod-and-now-i-get-an-error.19558/latest)
- **Antimatter Dimensions**: `checkPlayerObject()` recursively walks the whole save and collects every NaN (number or the string "NaN") with its property path: "N NaN player properties found: <paths>". Such a save is rejected with "Could not load the save (format unrecognized or invalid)." After migrations, a deep-merge fills missing fields from the default player object. — [AD source: storage.js](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/storage/storage.js)
- **Factorio**: each save records which migrations it has applied, so they run exactly once. References to removed prototypes become invalid, and ghost entities that can no longer be built may be removed instead of migrated. — [Factorio Lua API: Migrations](https://lua-api.factorio.com/latest/auxiliary/migrations.html)
- **Pokémon (Gen III/IV)**: per-slot checksums are recomputed at load, and a failed newest slot falls back to the older one with a message to the player. — [PokéBase (community)](https://pokemondb.net/pokebase/396866/what-caused-this-save-file-been-corrupted-previous-save-loaded)
- **RimWorld** warns about a mod mismatch at load and lets the player continue. Errors from unresolved references go to the log, and the first one is usually the cause. — [Steam discussion](https://steamcommunity.com/app/294100/discussions/0/144512526681622415); [RimWorld Wiki](https://rimworldwiki.com/wiki/Modding_Tutorials/Troubleshooting)
- **Vendor-blog advice** (lower quality): you can't stop a determined offline cheater, but you can detect the impossible: currency beyond what elapsed time allows, a multiplier with no legitimate source, a negative value from overflow. — [Bugnet: idle offline progress](https://bugnet.io/blog/how-to-fix-idle-game-offline-progress-wrong)

### Inferences
- **What the project has** (`save_format.gd`): `_check_shape()` verifies required containers and types (profile, plot, population, inventory, buildings with id/type/position/storage/queue/timer). `_drop_unknown()` removes buildings and goods whose ids are gone from `data/*.json` and adds player-visible warnings ("Removed a building the game no longer has (%s)."), which works much like SMAPI's Error Handler.
- **What's missing compared with good practice**:
  1. *Value invariants*: `_is_number()` accepts NaN and ±INF. No check exists for negative stock or worker counts, cash below any allowed floor, duplicate building ids, overlapping or out-of-grid positions, `next_building_id` ≤ an existing id, timestamps far in the future (beyond a tolerance of `now`), queue entries pointing to recipes no longer in data, or storage above capacity. A `validate_and_repair(state, data, now)` step can clamp or remove these and write a warning per repair, in the existing `save_notes` style. It is pure logic, so it belongs in `scripts/sim/` and can be covered by `tests/test_simulation.gd`.
  2. *Check before saving, not only at load*: AD's pattern is to refuse to persist NaN. Running the same check in `save_game()` and refusing to write (keeping the last good file, logging loudly in debug builds) stops a logic bug from spreading into the save and its backup within seconds (§3).
  3. *Fill instead of reject for optional fields*: like AD's deep-merge with defaults, missing optional fields could be filled from `Simulation.new_game()` defaults rather than failing the whole load.
  4. *Recipes and resources inside queues and storage*: `_drop_unknown()` covers top-level buildings and the inventory, but not resources inside a building's `storage` or recipes inside its `queue` (from reading the code). Those would reach screens that look them up, which is the crash `_drop_unknown()` exists to prevent.
- Possible failure chain worth checking (Godot-specific, for the other researchers): if a NaN or INF ever gets into `state`, how does `JSON.stringify` write it? If it writes a token that `JSON.parse` rejects, the main save *and* its seconds-old backup would both fail to parse on the next start. `_load_game()` would then keep the files but start a **new game**. A save-time NaN/INF guard (point 2 above) closes this.
- Debug builds could run the full invariant check after every simulation step (cheap at this scale) to catch rule bugs during development. This fits the project's existing debug-tools rule.

### Gaps
- I found no published write-ups of *commercial* sim games (Paradox, Klei) describing their load-time state validators. Most evidence comes from open-source or mod-loader code (SMAPI, AD, Factorio's mod API).

## 7. Player-side support workflows: finding and sending logs and saves (Android and PC)

### Takeaway
On PC, the low-effort workflows turn logs into a link with one action (HugsLib Ctrl+F12 → gist, smapi.io/log, Fabric/mclo.gs, a CS2 "Copy" button) and tell players exactly where files live and *when* to grab them (Klei: before relaunching). On Android, players often can't reach the files at all (`Android/data` is closed since Android 11), so mobile games lean on in-game support buttons and player IDs, and the save is server- or platform-backed. An offline single-player Android game needs its own in-game export path.

### Cited Findings
- **Stardew Valley save locations by platform**: Windows `%appdata%\StardewValley\Saves`; Mac/Linux `~/.config/StardewValley/Saves`; Android `Android/data/com.chucklefish.stardewvalley/files/Saves`; iOS via the Files app. Moving saves between PC and Android requires adding or removing a `.bin` extension. — [Stardew Valley Wiki: Saves](https://stardewvalleywiki.com/Saves)
- **Android 11+**: `Android/data/` is unreachable even for file managers. Stardew players asked (2023-11-22, bumped 2024-03-25) for a user-selectable save location; no developer reply appears in the thread. — [Stardew Valley forums](https://forums.stardewvalley.net/threads/android-option-to-change-the-save-game-location.25172/latest); [Android Developers: Android 11 storage](https://developer.android.com/about/versions/11/privacy/storage)
- **SMAPI log parser**: upload to smapi.io/log and share the link. The page puts "mods that need updating" at the top. — [Stardew Valley Wiki: Modding troubleshooting](https://stardewvalleywiki.com/Modding:Player_Guide/Troubleshooting)
- **HugsLib Log Publisher (RimWorld)**: Ctrl+F12 → Upload → Copy gives a gist link with the log and mod list, and mod authors make it mandatory. — [Steam Workshop discussion](https://steamcommunity.com/workshop/filedetails/discussion/1541721856/1735468061769788888/?ctp=9)
- **Fabric**: share crash reports through paste sites, not screenshots. — [Fabric docs](https://docs.fabricmc.net/26.1.2/players/troubleshooting/crash-reports)
- **Klei (ONI)**: send `Player.log` before relaunching. Exact paths are given for the log, crash dumps, local saves, cloud saves and auto-saves. — [Klei support](https://support.klei.com/hc/en-us/articles/360029555392)
- **Factorio**: the log is required in every bug report. Desync zips are auto-written to `archive/`. Automatic crash upload is opt-out. Reports belong on the official forum. — [Factorio Wiki: Log file](https://wiki.factorio.com/Log_file); [FFF #188](https://factorio.com/blog/post/fff-188); [FFF #231](https://factorio.com/blog/post/fff-231)
- **Cities: Skylines II** error pop-up has a "Copy" button for the error text. — [Steam discussion](https://steamcommunity.com/app/949230/discussions/0/4361249459071461316)
- **Paradox**: crash folders with `error.log` and `exception.txt` under Documents, plus a Crash Reporter that offers to send. — [Paradox forum](https://admin-forum.paradoxplaza.com/forum/threads/constant-crashes-on-the-desktop-also-wont-let-me-send-the-crash-report.1733922)
- **Mobile (EA, Playrix, etc.)**: lost-progress requests revolve around an in-game player ID quoted to support (EA forum threads are literally titled with the player ID, e.g. "Lost progress restoration - playerID …") and a Help & Support / Contact Us entry in the game's settings. Restores are rollbacks on the server side. — [EA Forums (PvZ 3)](https://forums.ea.com/discussions/plants-vs-zombies-3-technical-issues-en/lost-progress-restoration---playerid-18133013477/13150582); [EA Forums (PvZ 2)](https://forums.ea.com/discussions/plants-vs-zombies-2-en/plants-vs-zombies-2---progress-lost-after-update/12266660)
- **Google Play Games Saved Games** and **Android Auto Backup** are the platform routes for moving or restoring an Android save without the player touching files (limits in §3). — [PGS Saved Games](https://developer.android.com/games/pgs/savedgames); [Auto Backup](https://developer.android.com/identity/data/autobackup)

### Inferences
- **Recommended additions for this project, in rough priority** (all are inferences from the cases above, ordered by value to a solo developer with an offline Android game):
  1. **"Copy support info" button** (Settings): copies a short text block with game version, `save_version`, platform/OS, the last N `save_notes` and warnings, the last error code (§1), and offline seconds at last start. It pastes into an email or Discord like the CS2 "Copy" button or the SMAPI link, with no file hunting.
  2. **Export save / Import save** through the Android share sheet or as clipboard text (AD, Cookie Clicker and Melvor all have save export). This is the only practical way for an Android player to send a save to the developer or keep their own backup, because of the Android 11 `Android/data` lockdown.
  3. **Keep the previous session's log** (Factorio's `-previous.log`) so a crash isn't wiped by the relaunch. Klei had to tell players to grab the log before relaunching.
  4. **Short error codes** in every failure message (§1), so player reports can be grouped.
  5. **A visible note after any automatic repair or fallback** ("We loaded your save from 2 minutes earlier because the newest one was damaged; the damaged file was kept."). The project already does this via `save_notes`; keep it, and surface it in a dismissible panel.
  6. Later (MMO phase): a player ID shown in Settings, and server-side rollbacks, as mobile studios do.

#### Consolidated: what this project is still missing compared with good practice
(Already in place: temp-file + rename, one backup, damaged files kept, newer versions refused, step migrations, structure check, unknown-content removal with player notes, clamped negative offline time, save on pause/close, timestamps instead of countdowns.)
1. Make sure data reaches the disk before the rename (flush/sync). This is a Godot-specific question for the other researchers. — §3
2. Read back and parse the temp file before swapping it in. — §3
3. Time-spaced backups (last few + session-start + daily + pre-offline-catch-up + pre-migration), not one backup that is seconds old. — §3, §4, §5
